# J-01 — Plan de implementación

**Objetivo:** frontend estático infantil con TG-01, autorización supervisada, diario recuperable y entrega idempotente del contrato 1.0.
**Arquitectura:** DOM accesible y Canvas 2D; IndexedDB transaccional; API externa como autoridad. Simulador exclusivamente de desarrollo/pruebas, fuera del grafo productivo.
**Stack:** TypeScript, Vite, Vitest, Playwright; dependencias fijadas y lockfile.
**Specs:** `especificaciones-juegos/{README,01-aplicacion-web-tareas-digitales,contrato-runtime-v1}.md`.
**Ejecución:** nativa en esta sesión, sin delegación, commits automáticos ni cambios a Kudlab backend/frontend. No se requieren skills Superpowers no instaladas.

## Decisiones aprobadas

El responsable confirmó raíz actual y P-01/02/03/04/05/07/08 + RFC 8785 para desarrollo sintético. P-06/P-09 fuera. P-10 no implementa endpoints nuevos. G-01…04 no habilitados; código/gráficos propios eliminan dependencia de activos del demo, no aprueban metodología.

## Restricciones globales

- TG-01: 120000 ms; escenario 960×600; seis carriles; segmentos [0,40000,80000,120000]. Configuración estricta, no parámetros de dificultad.
- FULLY_VISIBLE, POINTER_V1, escala mínima 0.6, hueco máximo 250 ms.
- No iniciar offline; no reanudar medición tras recarga; identidad estable de claim/start/submission.
- Diario incremental, un sobre inmutable, acuse coincidente antes de borrar evidencia/secretos.
- Sin cookies docentes, terceros, secretos en URL/logs/Cache API ni purga automática de pendientes.
- Recursos nuevos propios. No afirmar precisión física, integración J-02, accesibilidad universal ni habilitación con menores.

## Revisión de fallos prioritarios

1. Respuesta perdida después de commit de claim/start/resultados: conservar identidad y reconciliar (tareas 1–3).
2. Recarga durante escritura y cierre: recuperar último checkpoint del reloj original, nunca prolongar ensayo (tarea 2).
3. Pestaña suspendida/lease vencido: impedir segundo ensayo y emisor concurrente (tareas 2–3).
4. Cuota o almacenamiento de iframe bloqueado: bloqueo preflight o interrupción honesta (tareas 2, 5).
5. Cambio de build con pendientes antiguos: migración aditiva, sin borrar bandeja ni cachés en uso (tarea 5).
